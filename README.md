# 랜덤 벙커디펜스 — 뽑고 · 합치고 · 사방을 막는다

**취향에서 출발한 첫 프로토타입.**

앞선 셋(game_test1 · DELVE · REAP)은 전부 내가 장르를 고르고 만들었고 전부 재미없었다.
그래서 재미의 축 넷을 1분짜리로 만들어 직접 고르게 했고(`../taste`), 두 가지가 나왔다.

- 본인 말: **"난 스타나 워크 유즈맵같은게 재밌던데"**
- 넷 중 손이 제일 오래 간 것: **①불어난다** (숫자가 커지고 자동으로 늘어남)

그 교집합이 이것이다. 유즈맵 랜타디의 루프 그대로:

```
뽑는다 → 합친다 → 배치한다 → 웨이브가 자동으로 온다 → 골드 → 또 뽑는다
```

```
node serve.mjs      # http://127.0.0.1:8772/
```

`R` 뽑기 · `M` 합치기 · `스페이스` 라운드 시작. 타워를 누르면 사거리가 보이고, 빈 칸을 누르면 옮긴다.

## 네 가지가 각각 다른 재미를 맡는다

| | 무엇을 맡나 |
|---|---|
| **뽑기** | 무엇이 나올까. 값이 뽑을수록 올라 무한 뽑기를 막는다 |
| **합성** | 같은 종류·등급 셋 → 한 등급 위. **숫자가 커지는 맛**이 여기 있다 (등급당 피해 ×3) |
| **배치** | 길에서 먼 자리는 사거리가 안 닿는다. 합칠 때는 길을 제일 많이 덮는 자리를 남긴다 |
| **관전** | 웨이브 중에는 손댈 것이 없다. 짜 놓은 것이 나 없이 막는 걸 본다 |

**상급 이상은 뽑기로 안 나온다.** 합성만이 길이어야 셋을 모으는 행동에 값이 생긴다.

## 재미를 숫자로 먼저 잰다

```
node funtest.mjs 8
```

물어보는 건 하나다 — **다음 라운드를 누르고 싶은가.** 그건 "뽑고 합치는 게 실제로
성장으로 이어지는가"로 잴 수 있다. 그래서 **놀았을 때와 아무것도 안 했을 때를 나란히 돌린다.**

| | 도달 라운드 | 최고 등급 | 총 화력 |
|---|---|---|---|
| 뽑고 합치며 논다 | **11.3** | 3등급 | 391 |
| 아무것도 안 한다 | 3.0 | 1등급 | 0 |

성장이 실제로 결과를 바꾼다. (봇은 "살 수 있는 만큼 다 뽑기"라 최적이 아니다 —
배치를 신경 쓰면 더 간다.)

## 눈으로 잡은 것

첫 렌더에서 **길이 안 보였다.** 길 타일 색이 배치 칸과 거의 같고 칸마다 2px 틈이 있어서,
몹이 어디로 가는지 안 읽혔다. 그러면 어디에 놓을지가 감이 아니라 운이 된다.
→ 길만 틈 없이 붙이고 한 단계 밝게, 들어오는 곳과 새는 곳에 표시를 달았다.
(DELVE 마을 지도에서 배운 것과 같다 — **이어져 보여야 이어진 것이다.**)


## 길 따라가기 → 벙커디펜스 (2026-08-03)

병수님 지적: *"유즈맵 중에 벙커디펜스라고 있는데, 중앙에 고정 구조물이 있고 거기에 유닛을
배치하면서 사방에서 몰려오는 적을 잡는 게임"*.

맞는 지적이었다. **길을 따라가는 구조에서는 배치가 사실상 "길 옆이냐 아니냐" 하나뿐이다.**
가운데 지킬 것을 놓고 사방에서 오게 하면 배치가 진짜 결정이 된다 — 한쪽에 몰아 세우면
반대쪽이 그대로 뚫리고, 고르게 펴면 어디도 두껍지 않다.

바뀐 것:

- **본진**이 가운데 3×3. 목숨 대신 **본진 체력**이고, 적은 붙어서 계속 때린다
- 적은 화면 밖 사방에서 **곧장** 본진으로 온다. 라운드가 오를수록 **갈래가 는다**(최대 4)
- **타워가 방벽이 된다.** 적은 가는 길에 타워가 있으면 그걸 먼저 친다 — 바깥에 세우면
  일찍 요격하지만 얻어맞고, 안쪽은 안전하지만 본진이 먼저 맞는다.
  웨이브가 끝나면 성한 것은 스스로 추스른다(잃는 것은 완전히 부서졌을 때뿐)
- **놓을 수 있는 곳은 본진 둘레 두 칸뿐.** 판 전체를 열어 두면 뽑은 것이 아무 데나 떨어져
  절반이 장식이 된다. 바깥 땅은 적이 달려오는 자리로 비워 둔다 — 요격할 시간이 거기서 나온다
- 사방 직진은 경로형보다 **요격할 시간이 훨씬 짧다**(길이가 아니라 반지름이 거리다).
  그래서 적을 늦추고, 수를 줄이고, 사거리를 넓혔다

### 배치가 게임인가 — 숫자로 확인

같은 뽑기·합성을 하되 **배치만 다른 봇 둘**을 나란히 돌린다.

| | 평균 도달 |
|---|---|
| 아무렇게나 세운다 (뽑힌 자리 그대로) | **2.3R** |
| 오는 쪽을 보고 세운다 | **8.8R** |
| 보고 세우고 + 유물을 쓴다 | **9.3R** |

배치 하나로 네 배 가까이 갈린다. 이 구조를 택한 이유가 숫자로 확인된다.


## 에셋과 UI (2026-08-04 밤)

### 에셋 — 한 세트로 읽히게

스프라이트 21종을 PixelLab MCP 로 구웠다(`tools/pixellab/gen.py`). **시점·조명·팔레트를
설명에 못 박아 두는 것이 전부다** — 안 그러면 유닛은 옆에서 본 그림, 적은 위에서 본 그림이
되어 같은 판에 못 세운다(DELVE 마을 아이콘이 그랬다).

| | 무엇 |
|---|---|
| `unit/` | 본진 + 유닛 8종. 전부 위에서 비스듬히 본 아이소메트릭 |
| `mob/` | 적 6종 (보스 포함) |
| `fx/` | 타격·폭발·서리·번개 |
| `ui/` | 바닥 두 종 (내 터 / 바깥 땅) |

**적은 CSS 로 붉게 물들인다.** PixelLab 이 초록으로 뽑아 놓았는데, 아군과 색이 안 갈리면
난전에서 누가 누군지 모른다. 다시 굽는 대신 `grayscale→sepia→hue-rotate` 로 색만 돌렸다
(`hue-rotate` 만 쓰면 근사 행렬이라 초록에서 파랑으로 샌다 — 실제로 그랬다).
서리를 맞은 놈은 같은 방식으로 파랗게 식는다.

**바닥은 배경이지 주인공이 아니다.** 타일 그림을 그대로 깔았더니 바닥이 유닛보다 눈에
띄었다 — 어두운 막을 덮어 톤을 죽이고, 바깥 땅을 내 터보다 더 어둡게 해서 "여기가 내
자리"가 먼저 읽히게 했다.

### 겪은 함정

- **`get_map_object` 의 파라미터는 `object_id` 다.** `map_object_id` 로 부르면 오류 없이
  빈손으로 돌아온다 — 21개가 전부 두 시간을 시간만 흘려보냈다. 이미 큐에 들어간 id 로
  다시 받아 와 다시 굽지 않았다.
- **정적 서버가 `public/` 을 안 보고 있었다.** Vite 쓰던 습관대로 에셋을 `public/assets` 에
  뒀는데 이 서버는 루트만 봐서 스프라이트가 통째로 404 였고, 화면에는 글자만 남았다.
- **끝난 화면은 판 전체를 덮어야 한다.** 게임오버 오버레이가 전장 안에 있어서 유닛과 피해
  숫자가 그 위로 뚫고 나왔다. `position:fixed` 로 화면 밖으로 뺐다.
- 이미지 `onerror` 에서 `this.remove()` 를 먼저 하면 `parentNode` 가 null 이 된다.
  표식을 먼저 달고 지운다. 다시 그려 떨어져 나간 뒤에 실패가 오는 경우까지 막아야 한다.

## 콘텐츠 (같은 날 밤)

- **유닛 4종 → 8종.** 숫자만 다른 유닛은 늘려 봐야 목록만 길어진다 — 저마다 "이건 이럴 때
  쓴다"가 달라야 한다. 관통(레일건) · 처치 골드(정찰기) · 붙은 놈 전담(지뢰밭) · 근거리
  연사(화염방사)를 더했다.
- **한 판에 나오는 것은 다섯 종뿐.** 여덟을 다 풀면 같은 것 셋 모으기가 두 배로 어려워져
  합성이 사실상 막힌다. 다섯으로 좁히면 확률이 돌아오고, 무엇보다 **판마다 조합이 달라진다**
  — "이번 판은 레일건이 없네"가 그 판의 성격이 된다.
- **중급이 섞여 나오게 고쳤다.** 예전 식은 1라운드 중급 확률이 0% 여서 상급 하나에 하급
  아홉이 필요했다 — 열 라운드 안에 도달할 수 있는 수가 아니었다.
- 뽑기 값의 기울기를 낮추고(2 → 1.15/회) 유물을 후하게 풀었다.
- **가진 것을 진열대로.** 여덟 종이 되고 나니 글 목록은 훑어야 읽힌다. 그림 타일로 바꾸고,
  셋이 모인 칸은 초록으로 맥동하며 **눌러서 바로 합쳐진다.**
- **다음 웨이브가 어디서 오는지 미리 보여 준다.** 안 보여 주면 첫 라운드는 무조건 헛방이고,
  그건 배치가 아니라 운이다.

## 모바일 (2026-08-04 아침)

같은 와이파이의 폰에서 바로 들어온다 — 서버가 `0.0.0.0` 으로 열려 있고, 켤 때 LAN 주소를
같이 찍는다.

```
node serve.mjs
  http://127.0.0.1:8772/
  http://192.168.0.148:8772/   ← 같은 와이파이의 폰에서
```

- **viewport 가 없으면 폰이 데스크탑 폭(980px)으로 그린 뒤 축소한다** — 글자가 개미만 해진다.
  `user-scalable=no` 로 두 번 두드림 확대도 막았다. 배치하려고 칸을 두드리다 판이 튀면 안 된다.
- **세로 화면에서는 옆 패널이 아니라 아래 패널이다.** 290px 짜리를 그대로 두면 폰 폭의 3/4 를
  먹어 전장이 사라진다. 전장을 위에 두고 조작은 엄지가 닿는 아래로 내렸다.
- 뽑기·웨이브 버튼을 위쪽에 나란히 뒀다(세로에서만). 세로로 쌓으면 스크롤해야 뽑기가 나온다.
  **가로·데스크탑에서는 감춘다** — 아래에 같은 버튼이 이미 있고, 같은 일을 하는 버튼이 둘이면
  둘 다 안 읽힌다.
- 손가락이 닿는 크기로: 진열대 44 → 48px, 버튼 패딩 상향.
- 길게 눌러 메뉴가 뜨거나 당겨서 새로고침되면 판이 그대로 끊긴다 —
  `-webkit-touch-callout` · `overscroll-behavior` 로 막았다.
- **가로 모드가 더 낫다.** 격자가 13×9 가로형이라 세로에서는 위아래가 남는다.

검증: iPhone 14 Pro 크기(393×852 / 852×393)로 실제 렌더 — 가로 스크롤 0, 예외 0.
